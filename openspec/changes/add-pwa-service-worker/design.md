# Design: Add PWA Service Worker

## Technical Approach

Integrate `vite-plugin-pwa` (Workbox-based) into the Vite 8 build pipeline. Precache the app shell (JS/CSS/HTML/SVG) for instant offline loading and add runtime caching for Supabase API calls with `NetworkFirst`. Preserve the existing hand-crafted `public/manifest.json` via `manifest: false`. Guard SW registration behind a dynamic `import('virtual:pwa-register')` wrapped in `'serviceWorker' in navigator` so the jsdom test environment (580 tests) is unaffected.

## Architecture Decisions

| Decision | Options | Choice | Rationale |
|----------|---------|--------|-----------|
| SW tooling | vite-plugin-pwa vs workbox-cli vs manual | vite-plugin-pwa | Integrates with Vite build lifecycle, generates precache manifest from build output, provides `virtual:pwa-register` for clean registration. workbox-cli adds a separate build step; manual is unnecessary complexity. |
| Manifest strategy | Auto-generate vs preserve existing | `manifest: false` | `public/manifest.json` is hand-crafted (Spanish metadata, SVG icon with `purpose: any maskable`). Auto-generation would replace it unnecessarily. |
| Registration pattern | Inline in `index.html` vs virtual module in `main.tsx` | Virtual module in `main.tsx` | `virtual:pwa-register` provides type-safe `registerSW({ immediate: true })` with auto-update logic. Guarded by `'serviceWorker' in navigator` for jsdom compatibility — the guard is necessary because jsdom has no SW API. |
| Supabase caching | NetworkFirst vs StaleWhileRevalidate | NetworkFirst | Fresh nutritional data matters. `NetworkFirst` with 10s timeout ensures online users get current data; offline users get cache. `StaleWhileRevalidate` would serve stale data even when network is available. |
| Update strategy | autoUpdate vs prompt | autoUpdate | Nutrition app — data correctness trumps interruption. `skipWaiting: true` + `clientsClaim: true` activates new SW immediately without user prompt. 30KB SW is negligible. |

## Data Flow

```
main.tsx loads
  └─ 'serviceWorker' in navigator?
       ├─ FALSE (jsdom) → skip, no error
       └─ TRUE (browser)
            └─ await import('virtual:pwa-register')
                 └─ registerSW({ immediate: true })
                      └─ Workbox registers sw.js
                           ├─ install: precache assets/{*.js,*.css}, favicon.svg, index.html
                           └─ activate: clientsClaim + cleanupOutdatedCaches
                                └─ fetch intercept:
                                     ├─ precached URL? ──→ CacheFirst (instant)
                                     └─ supabase.co/*? ──→ NetworkFirst (10s timeout → cache fallback)
```

## Interfaces / Contracts

**vite-plugin-pwa virtual module** (provided by plugin at build time):

```typescript
// virtual:pwa-register (auto-generated by vite-plugin-pwa)
export function registerSW(options?: {
  immediate?: boolean
  onNeedRefresh?: () => void
  onOfflineReady?: () => void
  onRegistered?: (registration: ServiceWorkerRegistration | undefined) => void
  onRegisterError?: (error: unknown) => void
}): (reloadPage?: boolean) => Promise<void>
```

**Workbox runtime caching contract** (for Supabase API):

```
cacheName: 'supabase-api'
strategy: NetworkFirst (10s timeout, 50 entries, 24h TTL)
urlPattern: /^https:\/\/[a-z]*\.supabase\.co\/.*/i
```

## Testing Strategy

| Layer | What to Test | Approach |
|-------|-------------|----------|
| Unit | None new | No logic to unit-test — SW registration is a side effect |
| Integration | SW guard in jsdom | Existing 580 tests pass unchanged (jsdom has no `serviceWorker`) |
| E2E | N/A | Out of scope — no Playwright changes in this change |
| Manual | `pnpm build` + DevTools | Verify `dist/sw.js` exists, SW registers in Application panel, app loads offline |

## Migration / Rollout

No migration required. Additive change — only affects build output (`dist/sw.js`) and registration at runtime. Rollback: `pnpm remove vite-plugin-pwa` + revert 3 files + `pnpm install`.
